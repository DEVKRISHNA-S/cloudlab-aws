Route 53

DNS and domain routing

Purpose

Route 53 is AWS's DNS service — it translates human-readable domain names into the actual network destinations that serve your application.

Why this project uses it

This project's domain is resolved through a Route 53 hosted zone, which points visitors to the infrastructure serving the application, over HTTPS.

VPC

Cloud networking

Purpose

A Virtual Private Cloud is your own isolated network inside AWS — a private slice of the cloud with its own IP address range, subnets, and routing rules.

Why this project uses it

This project runs inside a single VPC (10.0.0.0/16). The EC2 instance sits in a public subnet with a controlled path to the internet; nothing else is exposed.

Open full lesson

EC2

Compute in the cloud

Purpose

EC2 (Elastic Compute Cloud) gives you a virtual server — a computer you rent by the hour or second, sitting in an AWS data center.

Why this project uses it

The backend of this website runs on a single EC2 instance inside the VPC's public subnet, serving the application continuously.

Open full lesson

Lambda

Serverless compute

Purpose

Lambda runs a small piece of your code in response to an event — without you provisioning or managing any server at all.

Why this project uses it

A small utility function in this project — handling a specific API request — runs on Lambda instead of the always-on EC2 instance, since it only needs to run occasionally.

Open full lesson

API Gateway

Expose your functions as APIs

Purpose

API Gateway is the front door for HTTP requests, turning them into events that trigger backend logic like Lambda.

Why this project uses it

This project's Lambda utility function is reachable at a single API Gateway route, which validates the incoming request before invoking the function.

Open full lesson

S3

Object storage

Purpose

S3 (Simple Storage Service) stores files — called objects — durably and at effectively unlimited scale, organized into containers called buckets.

Why this project uses it

This project's static frontend assets and backup files are stored in a private S3 bucket. The EC2 instance's IAM role is granted read/write access to that bucket only.

Open full lesson

CloudWatch & SNS

Observe your infrastructure, then get notified

Purpose

CloudWatch collects logs, metrics, and alarms from across your AWS resources, giving you visibility into what your infrastructure is actually doing.

Why this project uses it

This project sends EC2 system logs and Lambda invocation metrics to CloudWatch, with a simple dashboard covering CPU, requests, errors, and latency.

Open full lesson

IAM

Identity and access management

Purpose

IAM is AWS's front door lock and keycard system. It decides who is allowed to do what, to which resources, in your AWS account.

Why this project uses it

This project's EC2 instance runs with an IAM role instead of stored credentials. That role only grants permission to read/write the specific S3 bucket and CloudWatch log group it needs — nothing else.
