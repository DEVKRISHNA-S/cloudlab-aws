API Gateway

Expose your functions as APIs

What is it?
API Gateway is the front door for HTTP requests, turning them into events that trigger backend logic like Lambda.
Why does it exist?
Lambda functions have no built-in way to receive a web request. API Gateway provides routes, methods, and a public URL, then hands the request off to your code.
How this project uses it
This project's Lambda utility function is reachable at a single API Gateway route, which validates the incoming request before invoking the function.

The Problem

Without a managed entry point, exposing serverless functions to the web would mean building and securing your own HTTP layer. API Gateway solves this with a managed, scalable front door.

The request path

1Client sends an HTTP request
2API Gateway matches a route + method
3Request is passed to Lambda
4Lambda returns a response
5API Gateway sends it back to the client

Try the Route

GET/hello 
{
  "message": "Hello from Lambda"
}

Important Concepts

REST APIs
The original, feature-rich API Gateway type, with fine-grained request/response control.
HTTP APIs
A lighter, cheaper, lower-latency API Gateway type for simpler use cases.
Routes
A path like /hello that clients call.
Methods
The HTTP verb (GET, POST, etc.) a route responds to.
Integration
The backend a route is wired to — most commonly a Lambda function.
Authentication basics
API keys, IAM auth, or token-based authorizers controlling who can call a route.

Common Mistakes

  • Leaving a route completely open when it should require an API key or token.
  • Choosing a full REST API when a simpler HTTP API would do.
  • Not validating input at the gateway, pushing all validation into the function.
  • Forgetting to enable CORS for a route called from a browser.
