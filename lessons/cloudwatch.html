CloudWatch & SNS

Observe your infrastructure, then get notified

What is it?
CloudWatch collects logs, metrics, and alarms from across your AWS resources, giving you visibility into what your infrastructure is actually doing.
Why does it exist?
You can't fix — or even notice — a problem you can't see. CloudWatch turns raw activity from EC2, Lambda, and API Gateway into something you can watch, graph, and get alerted on.
How this project uses it
This project sends EC2 system logs and Lambda invocation metrics to CloudWatch, with a simple dashboard covering CPU, requests, errors, and latency.

The Problem

Distributed cloud systems fail quietly unless something is actively watching them. CloudWatch solves this by centralizing logs and metrics from every service into one place you can monitor and alert from.

Monitoring vs. Logging vs. Observability

Monitoring
Continuously watching predefined metrics (like CPU usage) to know the current state of a system.
Logging
Recording detailed, timestamped events for later inspection and debugging.
Observability
The broader ability to ask new questions about a system's behavior using logs, metrics, and traces together — not just the questions you planned for.

Amazon SNS — turning an alarm into a notification

A CloudWatch alarm can watch a metric all day, but someone still needs to be told when it fires. Amazon SNS (Simple Notification Service) is the messaging service that delivers that alert — to email, SMS, or another system.

1A CloudWatch alarm changes state (e.g. CPU > 80%)
2The alarm publishes a message to an SNS topic
3SNS fans the message out to every subscriber
4Subscribers (email, SMS, another Lambda) receive the alert
Topic
A named channel that a CloudWatch alarm (or anything else) publishes a message to.
Subscription
An endpoint — an email address, phone number, or another AWS service — that receives messages published to a topic.
Publish/subscribe
Publishers don't need to know who's listening; subscribers just need to be attached to the right topic.
Confirming a subscription
A one-time confirmation step (like clicking a confirmation email) before an endpoint starts receiving messages.

Important Concepts

Logs
Text records of events, like application output or server activity.
Metrics
Numeric measurements over time, like CPU percentage or request count.
Alarms
Rules that trigger a notification or action when a metric crosses a threshold.
Monitoring
Ongoing observation of a system's known, expected health signals.
Observability
The ability to understand unexpected system behavior from the data it produces.

Common Mistakes

  • Only checking logs after a problem is already reported by a user.
  • Setting no alarms at all until after an incident happens.
  • Logging so much noise that the useful signal gets buried.
  • Confusing 'no alarms firing' with 'the system is healthy'.
