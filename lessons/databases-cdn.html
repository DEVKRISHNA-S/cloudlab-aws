Databases & Content Delivery

DynamoDB, Redshift & CloudFront

What is it?
A tour of three services that give an application somewhere to store and analyze data (DynamoDB, Redshift) and a fast way to deliver content globally (CloudFront).
Why does it exist?
EC2 and Lambda handle compute, but almost no real application stops there — most need a database, and most benefit from caching content closer to users.
How this project uses it
This project doesn't use a database (it has no user data to store) or CloudFront (its traffic doesn't yet need global edge caching) — but if it grew to need one, DynamoDB would be the natural fit for its simple, structured progress data, and CloudFront would sit in front of its S3 assets.

The Problem

A single database server in one region is slow for distant users and doesn't scale automatically. These services solve different halves of that problem: managed databases that scale, and a CDN that moves content physically closer to visitors.

Important Concepts

DynamoDB
A fully managed NoSQL database that scales automatically with single-digit millisecond latency.
Redshift
A managed data warehouse built for large-scale analytics queries, not everyday transactional reads/writes.
CloudFront
AWS's content delivery network (CDN) — it caches content at edge locations close to users worldwide.
Edge locations
Physical points of presence CloudFront uses to serve cached content near the visitor.
Read/write capacity
How DynamoDB is provisioned (or scaled on-demand) to handle a given request volume.
Cache invalidation
Telling a CDN that cached content is stale and needs to be re-fetched from the origin.

Common Mistakes

  • Using Redshift for everyday application queries it wasn't designed for.
  • Choosing DynamoDB for workloads that need complex relational joins.
  • Forgetting to invalidate a CloudFront cache after updating the underlying content.
  • Not considering a CDN at all until global users start complaining about latency.

Mini Challenge

You now understand:
  • DynamoDB scales automatically for fast, simple data access patterns
  • Redshift is built for analytics, not everyday transactions
  • CloudFront moves content physically closer to users worldwide
