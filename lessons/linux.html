Linux

Operate your cloud server

What is it?
Linux is the operating system running inside this project's EC2 instance. Nearly every cloud server you'll touch professionally runs some flavor of Linux.
Why does it exist?
EC2 gives you the hardware; Linux is how you actually operate it — installing software, managing files, watching processes, and diagnosing problems.
How this project uses it
This section focuses only on the commands actually used to keep this project's EC2 instance running: navigating the filesystem, managing the web server process, and reading logs.

The Problem

A rented server is just an empty machine until you can control it. Linux's command line is the universal interface engineers use to install software, configure services, and troubleshoot issues on that machine.

Important Concepts

pwd / ls / cd
Show your current directory, list its contents, and move between directories.
mkdir / touch
Create a new folder, or create a new empty file.
cat
Print a file's contents to the screen.
cp / mv / rm
Copy a file, move (or rename) a file, and delete a file.
grep / find
Search inside file contents, or search for files by name/location.
chmod / chown
Change a file's permissions, or change who owns it.
ps / top
List running processes, or watch live CPU/memory usage.
systemctl / journalctl
Start, stop, and check services; read their system logs.
curl / wget
Make an HTTP request from the terminal, or download a file.
ssh
Log into a remote server securely over the network.

Terminal

A realistic simulation — nothing here runs on a real server.

linux@cloudlab:~

Common Mistakes

  • Running rm -rf without double-checking the path.
  • Editing config files without keeping a backup copy first.
  • Using chmod 777 to 'make a permission error go away'.
  • Never checking logs before restarting a service, so the real cause gets lost.

Mini Challenge

You now understand:
  • A short set of Linux commands covers most day-to-day server operations
  • Logs are almost always the fastest way to diagnose a problem
  • systemctl/journalctl are the core tools for managing services
