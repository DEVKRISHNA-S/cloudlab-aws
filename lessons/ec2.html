EC2

Compute in the cloud

What is it?
EC2 (Elastic Compute Cloud) gives you a virtual server — a computer you rent by the hour or second, sitting in an AWS data center.
Why does it exist?
Not every application fits a serverless model. Some workloads need a persistent, always-on environment with full control over the operating system — that's what EC2 is for.
How this project uses it
The backend of this website runs on a single EC2 instance inside the VPC's public subnet, serving the application continuously.

The Problem

Buying and maintaining physical servers is slow, expensive, and hard to scale. EC2 solves this by letting you provision a server in minutes, resize it on demand, and pay only for the time it runs.

The Mental Model

Your laptop
A physical computer you own, sitting on your desk.
EC2
A computer you rent from AWS, sized to your needs, that lives in a data center instead of your desk.

How EC2 works

1Choose an AMI (the OS image)
2Choose an Instance Type (CPU/RAM size)
3Attach Storage (EBS volume)
4Attach a Security Group (firewall rules)
5Launch → Running Instance

Important Concepts

AMI
Amazon Machine Image — a snapshot of an operating system and pre-installed software used to launch an instance.
Instance types
Predefined hardware sizes (like t3.micro or m5.large) trading off CPU, memory, and cost.
EBS
Elastic Block Store — persistent disk storage attached to an instance, surviving reboots.
Security groups
A virtual firewall controlling which traffic can reach the instance.
Public/private IP
A public IP is reachable from the internet; a private IP is only reachable inside the VPC.
SSH
The secure protocol used to remotely log into and control a Linux instance.
Key pairs
A public/private key used instead of a password to authenticate SSH access.
Regions
Separate geographic areas AWS operates in, like us-east-1 or eu-west-1.
Availability Zones
Physically isolated data centers within a region, used for redundancy.

Terminal

A realistic simulation — nothing here runs on a real server.

Common Mistakes

  • Losing the private key file and permanently locking yourself out.
  • Leaving an instance running after you're done experimenting.
  • Choosing an oversized instance type before knowing the real workload.
  • Storing application secrets directly on the instance instead of using IAM roles.

Mini Challenge

  • AMI + instance type + storage + security group define an instance
  • It's the right tool for persistent, always-on workloads
