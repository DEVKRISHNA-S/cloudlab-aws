Networking Fundamentals

How data actually moves

What is it?
The OSI and TCP/IP models describe how two computers exchange data — from raw electrical signals up to the application talking to you right now.
Why does it exist?
Every AWS service in this course — VPC, Route 53, API Gateway — is a cloud-shaped wrapper around ordinary networking. Without this layer, terms like 'subnet' or 'routing' are just vocabulary, not understanding.
How this project uses it
This project's own request path (visitor → Route 53 → VPC → EC2) is a real-world walk through the OSI model: DNS resolution, routing, and transport all happen before the application layer ever sees the request.

The Problem

Two machines can't just 'talk' — they need a shared, layered set of rules for addressing, routing, and framing data, agreed on by every device and vendor on the internet. Networking standards are that shared agreement.

The Mental Model

A postal system
An address format, sorting depots, and delivery trucks — layers that don't need to know what's inside the envelope.
The OSI Model
Physical wiring, addressing, routing, and application layers — each one only needs to trust the layer below it, not understand it.

The layers a request passes through

1Physical — electrical signals or radio waves on the wire
2Data Link — Ethernet frames between adjacent devices
3Network — IP addressing and routing between networks
4Transport — TCP/UDP breaking data into reliable segments
5Application — HTTP, DNS, and the protocols you actually recognize

Important Concepts

OSI Model
A 7-layer reference model describing how network communication is organized.
TCP/IP
The practical 4-layer protocol suite the real internet actually runs on.
Topologies
The physical or logical shape of a network — star, mesh, bus.
Ethernet standards
Rules governing how devices on a local network frame and send data.
Network hardware
Switches, routers, and firewalls — the physical devices that move and filter traffic.
WANs
Networks spanning long distances, connecting separate local networks together.

Common Mistakes

  • Treating the OSI model as something devices implement literally, rather than a mental map.
  • Confusing switches (Layer 2, local) with routers (Layer 3, between networks).
  • Assuming TCP and UDP are interchangeable — one guarantees delivery, the other doesn't.
  • Ignoring physical/hardware limits when diagnosing a 'software' networking problem.
