AWS Security Services

GuardDuty, Inspector & WAF

What is it?
Three AWS services that actively watch for threats: GuardDuty (account and network threat detection), Inspector (vulnerability scanning), and WAF (web application firewall).
Why does it exist?
IAM and security groups control who and what can act — but something still needs to actively watch for suspicious behavior, known vulnerabilities, and malicious web traffic in real time.
How this project uses it
If this project's traffic grew, GuardDuty would watch its account for anomalous API activity, Inspector would scan its EC2 instance for known vulnerabilities, and WAF would sit in front of its API Gateway route to block common web attacks.

The Problem

Firewalls and permissions stop known, expected categories of access — they don't notice a compromised credential behaving strangely, an unpatched vulnerability, or a SQL-injection attempt hidden in a request body. These services close that gap.

Important Concepts

GuardDuty
A threat-detection service that continuously analyzes account, network, and log activity for malicious behavior.
AWS Inspector
An automated vulnerability scanner for EC2 instances and container images.
AWS WAF
A web application firewall that filters malicious HTTP requests before they reach your application.
Findings
The alerts these services generate when they detect something worth investigating.
Managed rule groups
Pre-built WAF rule sets covering common attack patterns like SQL injection and cross-site scripting.
Continuous scanning
Inspector and GuardDuty run on an ongoing basis, not just once at deployment.

Common Mistakes

  • Enabling a security service once and never reviewing its findings afterward.
  • Assuming WAF alone replaces the need for secure application code.
  • Ignoring Inspector findings rated 'low' until they compound into a real vulnerability.
  • Not scoping WAF rules to the actual application, leading to false positives or gaps.
